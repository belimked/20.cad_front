# cad-drawing-processor 需求说明

## 背景与动机
- 现有 CAD 图纸以 DWG 为主，缺乏自动化转换与拆分能力，人工处理耗时且易出错。
- 目标是提供简单可靠的命令行工具，先将 DWG 批量转为 DXF，再依据图纸中的方框边界拆分成子 DXF。

## 范围界定
- **目标**：完成 DWG→DXF 转换与按方框拆分两个核心流程，并提供最小化的 CLI。
- **非目标**：不实现图形编辑、格式修复、云端存储、GUI 或批注功能；不负责生成测试图纸。

## 术语
- **DWG**：AutoCAD 原生二进制格式。
- **DXF**：AutoCAD 文本交换格式，便于解析。
- **方框**：由四条线段或折线闭合组成的矩形，用于区分区域。

## 用户故事（EARS 格式）
- 当用户提供包含 DWG 文件的目录时，系统应将该目录下的所有 DWG 转换为同名 DXF（置于输出目录），遇到失败需给出报告。
- 当用户提供 DXF 文件且文件内存在闭合矩形方框时，系统应为每个独立方框提取其内部实体并生成子 DXF，命名需可追溯原文件与方框序号。
- 当方框内包含嵌套或重叠图形时，系统应尽可能保留矩形内所有实体并忽略矩形外实体。
- 当检测不到任意矩形方框时，系统应记录警告并跳过拆分，避免生成空文件。

## 功能性需求
1. 提供一个命令将指定输入目录中的 DWG 批量转换为 DXF，可配置输出目录、覆盖策略与保留原始文件。
2. 提供一个命令读取单个 DXF，识别闭合矩形方框（支持 `LWPOLYLINE` 与 `POLYLINE`），为每个方框导出独立 DXF。
3. 拆分时需要把矩形边界本身连同矩形内的全部实体写入子 DXF，并保持图层、颜色等基础属性。
4. CLI 命令应返回非零退出码以指示失败，并输出详细日志文件/终端信息。
5. 支持最小的配置文件或命令行参数，避免硬编码路径，默认覆盖策略安全（不覆盖除非指定）。

## 非功能性需求
- 工具需兼容 macOS 与 Linux，Windows 覆盖作为加分但非必需。
- DWG→DXF 转换可依赖外部命令（如 ODAFileConverter），需在文档中说明安装要求与路径配置。
- DXF 解析与拆分逻辑需通过自动化测试验证基本场景（至少无矩形、单矩形、多矩形、嵌套矩形）。
- 日志与错误信息采用中文输出并尽量简洁易懂。

## 约束与开放问题
- 需确认可用的 DWG→DXF 转换工具及授权条款，暂预设使用本地已安装的 `ODAFileConverter` CLI。
- 方框识别目前仅针对严格矩形，若存在旋转或非正交形状需后续建模。
- 需要样例 DXF/DWG 以编写与验证测试，待用户提供或自行合成。

## 验收标准
- 提供 README 说明使用步骤、外部依赖与示例命令。
- 运行转换命令后，在示例输入目录下能得到正确的 DXF 输出且日志记录无致命错误。
- 对提供的示例 DXF 执行拆分命令，可在输出目录下看到按方框拆分的子 DXF，数量与命名满足用户故事描述。
