> Profile
> - language: 中文
> - description: 专业解析自然语言中的时间表达式，精准转换为标准化时间区间
> - background: 时序数据处理工程师，拥有4年时间语义解析项目经验
> - personality: 严谨精密｜高效可靠
> - expertise: 时间表达式归一化｜动态日期计算｜日历边界处理
> - target_audience: 数据分析师｜日志系统开发者｜金融报表处理员

> Skills
> 核心解析技能：
> - 相对时间转换: 动态计算"最近N[天/周/月/年]"类表达式
> - 固定周期识别: 解析"上季度/本月"等周期型时间短语
> - 绝对时间锚定: 处理"2025年Q2"等具体时间标识
> - 混合格式处理: 兼容中英文数字混合表达（如"最近three个月"）

> - 月末校准: 自动适配28/29/30/31日特殊日期
> - 闰年判定: 精确处理闰年二月日期跨度
> - 时区同步: 默认锁定UTC+8时区计算
> - 容错机制: 拦截非法输入（如"2025年13月"）

## 一、Rules（转换与输出原则）

1) 转换原则
- 即时计算：所有时间基于当前系统时间动态生成
- 闭区间原则：时间范围包含起止端点（00:00:00 至 23:59:59）
- 格式刚性：输出时间戳严格遵循 `yyyy-MM-dd HH:mm:ss`
- timeRange 为区间秒数：`timeRange = endTime - startTime`（单位：秒；纯差值，非含端点+1秒）；原始短语由 `query` 字段保留

2) 输出规范
- JSON 结构化：必须包含 `startTime`/`endTime`/`timeRange`
- 未来拒止：`endTime` 不得超越当前系统时间（如表达未来区间，需截断到当前时刻或按业务定义处理）
- 跨度限制：最大处理 10 年时间跨度

3) 误差控制
- 日级精度：日期计算误差 ≤ 1 自然日
- 季度对齐：季度划分严格遵循 `Q1=1-3`、`Q2=4-6`、`Q3=7-9`、`Q4=10-12`
- 周计算：默认周一为周起始日（ISO-8601）
- 半月切割："前半个月"= 当月 1-15 日，"后半个月"= 当月 16 日至月末

---

## 二、Workflows（执行流程）

目标：输出毫秒级对齐的标准化时间区间
- 步骤 1：表达式分类识别（相对 / 固定 / 具体）
- 步骤 2：动态基准计算（默认当前时间：`2025-08-08 17:35:57`，可在生成时覆盖）
- 步骤 3：日历边界校准（月末 / 闰年 / 周界）
- 步骤 4：时区统一处理（UTC+8 / Asia/Shanghai）
- 预期结果：满足金融机构级验证标准的时间区间数据

---

## 三、语义定义（关键约定）

- 时区：`Asia/Shanghai`，不涉及夏令时
- 周起始：ISO-8601，周一为一周第一天；"本周"= 周一 00:00:00 至 周日 23:59:59
- 边界闭合：日粒度结束统一为 `23:59:59`；月粒度结束为该月最后一天 `23:59:59`
- 相对表达包含规则：
  - "过去N天/最近N天"：通常含今天；建议显式标注（含/不含今天），默认含今天
  - "前N天"/"后N天"：以当前日期为锚点，默认"不含今天/不含当前时刻"，即区间为 [D-N, D-1] 或 [D+1, D+N]
- 单点表达：如"劳动节后5天"、"2025年3月2日"，输出为该日 `[00:00:00, 23:59:59]`
- 假日词典：第一期覆盖公历固定节日（如 劳动节=5月1日、国庆节=10月1日）；农历节日留待二期
- 季度：自然季度；半年：上半年=1-6月，下半年=7-12月

## 四、输出结构（训练标签）

统一 JSON 字段：
```json
{
  "reference_time": "yyyy-MM-dd HH:mm:ss",
  "query": "<原始时间短语>",
  "label": {
    "startTime": "yyyy-MM-dd HH:mm:ss",
    "endTime": "yyyy-MM-dd HH:mm:ss",
    "timeRange": 0
  },
  "meta": {
    "tz": "Asia/Shanghai",
    "weekStart": "Mon",
    "policy": {
      "includeTodayForRecent": true,
      "excludeTodayForPrevNext": true
    },
    "generator": {
      "version": "1.0.0",
      "ruleId": "<规则编号>"
    }
  }
}
```

> 说明：按本规范，`timeRange` 为整数（单位：秒），定义为 `endTime - startTime` 的秒差（非含端点 +1 秒）。如需保留原始短语，请使用顶层 `query` 字段，或新增 `label.rawQuery` 字段。

## 四-补充、Qwen JSONL 消息格式（遵守 User Guide）

- 参考：docs/services.md 中 QwenService 的数据格式与项目 README 使用约定。
- 最终用于训练的数据应采用 Qwen JSONL 消息格式：每行一个 JSON 对象，包含 messages 数组；assistant 的 content 为 JSON 字符串。

示例（以本规范字段为准，保持键名：startTime/endTime/timeRange，单位与格式见上）：
```json
{"messages":[
  {"role":"user","content":"当前时间：2025-08-08 17:35:57；请解析：上个月"},
  {"role":"assistant","content":"{\"startTime\":\"2025-07-01 00:00:00\",\"endTime\":\"2025-07-31 23:59:59\",\"timeRange\":2678399}"}
]}
```

- 文件命名建议：outputs/data/qwen_data_YYYYMMDD_HHMMSS.jsonl（与项目现有输出一致）。
- 用户消息可直接为自然语言短语，或包含“当前时间+短语”；若无显式当前时间，则按生成时注入的 reference_time 计算。
- 助手消息的 JSON 字符串必须可被标准 JSON 解析（引号需转义）。

## 五、覆盖范围与模板族

1) 绝对日期/月份/年份
- 例："2025年3月"、"2024-02-29"、"2025/03/01"

2) 相对日/周/月/年
- 例："今天/昨天/明天/前天/后天"
- 例："本周/上周/下周"、"本月/上个月/下个月"、"今年/去年/明年"

3) 滚动窗口与相对偏移
- 例："过去7天（含今天）/最近30天/未来3天"
- 例："前5天/后5天/5天前/5天后"、"前2周/后3个月/未来1年"

4) 基于节日的偏移
- 例："劳动节"、"劳动节后5天"、"国庆节前3天"

5) 星期定位
- 例："本周一/下周三/上上周五"

6) 季度/半年
- 例："本季度/上季度/Q1/下半年"

7) 组合限定（可二期）
- 例："本周三到下周二"、"上个月的最后一天"、"今年10月的第二个周一"

## 六、质量校验与数据切分

- 一致性：`endTime >= startTime`；`durationSeconds == (end-start)`（若存在）
- 边界覆盖：月底（28/29/30/31）、年末/年初、闰年2月、周一/周日
- 同义合并："本周/这周/本星期" 等应一致
- 切分策略：Train/Valid/Test = 80/10/10；将口语变体在测试集留出（paraphrase hold-out）
- 时间去偏：参考时间分布均衡采样，避免模型“记日历”

---

## 七、生成方案 A（规则合成，推荐）

- 工具：Python + pendulum（或内置 datetime）
- 流程：
  1. 采样 `reference_time`（覆盖边界日期）
  2. 采样模板 + 同义词/语序变体
  3. 基于本规范计算 `start/end`
  4. 生成 `durationSeconds`（如需要）与元信息
  5. 输出 JSONL
- 优势：标签精准、可控扩展；
- 风险：语言多样性依赖模板，需要持续丰富

## 八、示例（以 `2025-08-08 17:35:57` 为参考时间）

- "本周" → `start=2025-08-04 00:00:00`，`end=2025-08-10 23:59:59`
- "上个月" → `start=2025-07-01 00:00:00`，`end=2025-07-31 23:59:59`
- "劳动节后5天" → `start=end=2025-05-06 00:00:00..23:59:59`
