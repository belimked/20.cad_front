### 1.1 整体架构理解

**评审问题**：
- [ ] **架构分层清晰吗？**
  - 表现层（Svelte UI）
  - 应用层（Rust Tauri Commands）
  - 外部服务（远程 CAD 处理 API）

- [ ] **职责边界明确吗？**
  - 前端负责：UI 渲染、状态管理、轮询调度
  - Rust 负责：文件 I/O、HTTP 请求、系统集成
  - 远程 API 负责：CAD 处理、任务管理、PDF 生成

- [ ] **通信机制理解一致吗？**
  - 前端 ↔ Rust：Tauri IPC (invoke)
  - Rust ↔ 远程 API：HTTP/HTTPS (reqwest)

**关键图表**（参考架构文档第 2.1 节）：
```
前端 (Svelte) → Tauri IPC → Rust 后端 → HTTP → 远程 API
```

**评审输出**：

- [ ] 记录任何架构层面的疑问或建议

## 第二部分：关键技术决策评审 (30 分钟)

### 2.1 技术栈选择

#### Tauri 框架
- [ ] **Tauri 相对于 Electron 的优势理解清楚吗？**
  - 更小体积（< 10 MB vs > 100 MB）
  - 更低内存占用
  - 更好的安全性
  - 原生性能

- [ ] **团队是否有 Rust 开发经验？**
  - [ ] 有经验：继续
  - [ ] 无经验：需要学习时间（预估 1-2 周）

- [ ] **Tauri 1.5 的限制和约束了解吗？**
  - 不支持热更新（需完整重装）
  - Rust 编译时间较长
  - 调试相对复杂

**决策确认**：
- [ ] ✅ 确认使用 Tauri
- [ ] ⚠️ 需要进一步评估
- [ ] ❌ 重新考虑方案

#### Svelte 前端框架
- [ ] **Svelte 相对于 React/Vue 的优势理解吗？**
  - 编译时框架，无运行时
  - 更小的打包体积
  - 更简洁的语法
  - 内置响应式

- [ ] **团队 Svelte 经验如何？**
  - [ ] 有经验
  - [ ] 无经验但愿意学习
  - [ ] 强烈偏好其他框架

- [ ] **Svelte 生态是否满足需求？**
  - UI 组件库：自研或使用第三方（如 Carbon Components）
  - PDF.js 集成：无问题
  - 状态管理：内置 Stores 足够

**决策确认**：
- [ ] ✅ 确认使用 Svelte
- [ ] ⚠️ 考虑使用团队更熟悉的框架（React/Vue）

#### PDF.js 渲染引擎
- [ ] **PDF.js 性能可接受吗？**
  - 大文件（100+ 页）渲染时间
  - 内存占用
  - 滚动流畅度

- [ ] **是否需要 POC 验证？**
  - [ ] 需要：创建性能测试 Demo
  - [ ] 不需要：直接使用

- [ ] **是否考虑备选方案？**
  - 系统原生 PDF 查看器（调用系统默认程序）
  - 其他 PDF 库（如 pdf-lib、react-pdf）

**决策确认**：
- [ ] ✅ 确认使用 PDF.js
- [ ] ⚠️ 需要性能 POC 验证
- [ ] ❌ 考虑其他方案

#### 本地存储：tauri-plugin-store
- [ ] **存储容量需求明确吗？**
  - 目标：支持至少 1000 条历史记录
  - 预估单条记录大小：< 1 KB
  - 总容量：< 1 MB（非常小）

- [ ] **数据格式和结构确认吗？**
  - JSON 格式存储
  - 数据结构已定义（参考架构文档第 8.1 节）

**决策确认**：
- [ ] ✅ 确认使用 tauri-plugin-store

### 2.2 核心功能实现方案

#### 异步任务轮询机制
- [ ] **轮询间隔合理吗？**
  - 当前设计：3 秒
  - 是否需要动态调整？（如任务排队时降低频率）

- [ ] **停止条件清晰吗？**
  - 任务完成（completed）
  - 任务失败（failed）
  - 网络连接失败（重试 3 次后）

- [ ] **重试策略合理吗？**
  - 最多重试 3 次
  - 指数退避：5s → 10s → 15s

- [ ] **并发轮询处理方案？**
  - 当前设计：单任务轮询
  - 未来批量处理：需要支持多任务并发轮询

**决策确认**：
- [ ] ✅ 轮询方案确认无误
- [ ] ⚠️ 需要调整参数（轮询间隔/重试次数）

#### 文件上传实现
- [ ] **上传方式确认？**
  - Rust 后端使用 `reqwest` multipart 上传
  - 前端调用 Tauri Command

- [ ] **大文件处理策略？**
  - 文件大小限制：100 MB（警告）
  - 是否需要断点续传？（MVP 阶段：否）
  - 超时时间：60 秒

- [ ] **进度反馈实现？**
  - 当前设计：Rust 发送事件到前端
  - 前端订阅事件更新进度条

**决策确认**：
- [ ] ✅ 上传方案确认
- [ ] ⚠️ 需要调整大文件限制或超时时间

#### 文件关系可视化（SVG 连线图）
- [ ] **实现复杂度评估？**
  - 使用 Svelte + SVG 实现
  - 动态计算卡片位置
  - 响应式布局（窗口 resize）

- [ ] **是否需要技术验证？**
  - [ ] 需要：创建连线图 POC
  - [ ] 不需要：方案清晰可行

- [ ] **交互细节确认？**
  - 悬停高亮
  - 点击选中
  - 动画效果

**决策确认**：
- [ ] ✅ 可视化方案确认
- [ ] ⚠️ 需要简化方案（如使用箭头图标代替 SVG）

#### PDF 预览功能
- [ ] **预览器功能范围确认？**
  - ✅ 缩放、旋转、翻页（必需）
  - ✅ 页码跳转（必需）
  - ⚠️ 缩略图侧边栏（可选，Epic 4 Story 4.4）

  - 懒加载页面（仅渲染可见页面 + 前后各 2 页）

- [ ] ✅ 预览功能范围和优化策略确认

## 附录：快速参考

### 架构关键数字

- **技术栈**: Tauri 1.5 + Svelte 4 + Rust 1.75+
- **轮询间隔**: 3 秒
- **重试次数**: 3 次
- **上传超时**: 60 秒
- **查询超时**: 10 秒
- **下载超时**: 5 分钟
- **历史记录容量**: 1000 条
- **PDF 缓存页数**: 20 页

### 核心 Tauri Commands

1. `select_file` - 文件选择
2. `upload_file` - 文件上传
3. `poll_task_status` - 状态查询
4. `generate_pdf` - PDF 生成
5. `download_pdf` - PDF 下载
6. `save_task_history` - 保存历史
7. `load_task_history` - 加载历史
8. `clear_history` - 清除历史
9. `show_notification` - 显示通知

### 核心 Svelte Stores

1. `taskStore` - 任务状态
2. `fileStore` - 文件状态
3. `historyStore` - 历史记录
4. `relationshipStore` - 文件关系
5. `uiStore` - UI 状态
6. `configStore` - 配置
